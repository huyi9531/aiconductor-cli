# 小红书笔记拆解

## 概述

此 Skill 通过全局安装的 `aiconductor-cli` 取一条小红书笔记的详情与评论，回答两个问题：**这条为什么爆/为什么不爆**、**读者到底在说什么**。

适用环境默认已配置好 CLI 和 API Key。当遇到 `command not found`、缺少密钥、鉴权失败或版本不兼容时，读取 [references/aiconductor-skills-setup.md](references/aiconductor-skills-setup.md)，修好后重试原命令一次；再失败就把原始错误交给用户。仅当用户明确要求初始化或配置 Skill 时才主动读取该文件。

## 什么时候用

- 看到一条爆款，想知道它踩中了什么、能不能复刻
- 自己发的笔记数据不如预期，想找原因
- 想知道评论区在夸什么、在吵什么、在问什么

不接这几种，直说原因：

| 不接的请求 | 原因 |
|---|---|
| 这个赛道什么在爆 | 那要批量搜，属于选题技能 |
| 这个账号怎么样 | 账号维度是另一条链路 |
| 把图片/视频里的字扒出来 | 需要 OCR，当前 CLI 没暴露该能力 |
| 下载笔记里的图片和视频 | 不提供 |
| 抖音/B站同款内容 | 只做小红书 |

## 执行

### 1. 取笔记详情

```bash
aiconductor-cli xhs note "<链接或分享口令>" -f text
```

输入支持三种形态，脚本会自动识别，**不要让用户手动找 note_id**：

- 笔记链接 `/explore/<id>` 或 `/discovery/item/<id>`
- `xhslink.cn` / `xhslink.com` 短链（会自动跟随跳转）
- 用户复制出来的整段分享口令（形如「标题 https://xhslink.cn/o/xxx 复制内容，然后进入【小红书】查看相关笔记。」）

需要结构化数据时去掉 `-f text`，字段在 `data.note_data`。

### 2. 取评论区

```bash
aiconductor-cli xhs comments "<同一链接>" --max-pages 2 -f text
```

一页约 10 条，按点赞降序展示。**用户没特别要求就取 2 页**（约 20 条）足够判断舆论倾向；评论很多而用户只要"大概风向"时取 1 页即可。

### 3. 读数据

| 信号 | 怎么读 |
|---|---|
| 藏/赞 > 1 | 攻略、清单、教程型，用户觉得"以后用得上"——最容易被复刻的爆款形态 |
| 藏/赞 0.3–1 | 正常种草/观点内容 |
| 藏/赞 < 0.2 | 靠情绪、热点或账号存量，内容本身可复用性低 |
| 评/赞 > 0.1 | 引发了讨论或争议，适合做"有共鸣/有对立面"的题 |
| 评/赞很低但赞高 | 内容是"看完就走"型，评论区没有增量信息 |

**不要**用阅读量判断：小红书详情接口的阅读量字段实测恒为 0。

### 4. 读内容结构

拆这五处，别通篇复述：

1. **标题**：有没有具体数字、身份标签（"26 岁女程序员"）、反差（"AI 很好，能背锅就更好了"）
2. **开篇两句**：是不是直接给结论或抛冲突
3. **正文长度与分段**：短句多还是长段多；有没有清单/步骤
4. **话题标签**：用了几个、是不是都在蹭热门话题
5. **形式**：图文（几张图）还是视频（多长）——同赛道不同形式的表现差异要指出来

### 5. 读评论区

按点赞排序看前 10–20 条，归纳这四类，**结论一律挂原话**：

- **共鸣点**：最多人点赞的那几句反映了什么情绪
- **争议双方**：有对立观点时把双方原话各引一句，别站队
- **高频问题**：反复出现的"求链接/怎么买/在哪看"说明内容缺了一块，这就是下一条的选题
- **未被满足的需求**：用户在评论里索要但笔记没给的东西

评论区里只有一级评论 + 上游返回的可见楼内回复；**不要声称"看了全部评论"**。

### 6. 交付

固定四段：

1. **数据面板**：点赞 / 收藏 / 评论 / 分享、藏/赞比、评/赞比、发布时间、形式（图文 N 图 / 视频 Ns）
2. **内容拆解**：按上面五处讲，每条都要挂原文片段
3. **评论区**：共鸣点、争议双方、高频问题（每条挂原话）
4. **可复刻结论** 2–3 条：说清"照这个写，要踩住哪个规律"，以及"这条的成功能不能脱离作者本身"（如果能，就是可复刻的；如果靠账号存量，明说）

## 失败怎么说

| 现象 | 多半是 | 怎么讲 |
|---|---|---|
| 命令报「无法从输入里识别小红书笔记」 | 粘贴的不是笔记链接 | 让用户重新复制笔记的分享链接 |
| `success` 为 `false` 且 message 含"无效或不可访问" | 笔记被删/仅自己可见 | 原话说清楚，别猜内容 |
| 短链报网络错误 | 短链服务不可达 | 让用户直接粘贴长链接（浏览器打开后复制地址栏） |
| 评论返回 0 条 | 评论被关闭或笔记太新 | 直说"评论区暂无可用数据"，正文结论照给 |
| `has_more` 为真 | 只取了一页 | 结论标注"只看了 N 页评论" |

## 限制

- 只读一级评论 + 上游返回的可见楼内回复，拿不到完整二级/三级楼中楼
- 图文笔记的正文经常在图片里，`desc` 可能只有话题标签；**本技能不提取图内文字**——遇到这种情况直接说"正文在图里，数据与评论仍可分析"
- 数据是抓取时点的快照，`time` 已换算成北京时间
- 不下载素材、不做图片 OCR、不跨平台对比
